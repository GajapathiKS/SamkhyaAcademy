# Forward Deployed AI Leadership

## Module 4: 90-Day Execution Blueprint

Present a 90-day plan with a decision gate rather than a guaranteed outcome.

### 4.1 Select priority use cases

Select a small set of use cases that share a measurable goal and a ready owner. Sequence dependencies deliberately. Do not launch every candidate simply because the technology is available or competitors are discussing it.

### 4.2 Define pilot and metrics

Define the pilot’s audience, baseline, measures and guardrails before launch. Pair efficiency measures with quality and risk measures. Decide how results will be collected so the final review does not depend on anecdotes.

### 4.3 Set governance checkpoints

Schedule checkpoints for data access, evaluation, user readiness and incident handling. Each gate needs a decision owner and evidence. A checkpoint should be able to stop or revise the work, not merely confirm that a meeting happened.

### 4.4 Present the 90-day plan

Present scope, owners, cost assumptions, delivery phases and stop/scale criteria. Distinguish committed work from hypotheses. The plan should explain what leadership will decide at day 90 and what evidence would justify a different direction.

## Worked lab

Days 1-30: baseline, data permissions, task evaluation
Days 31-60: bounded pilot and trained reviewers
Days 61-90: measure quality, cost and adoption; review incidents
Final decision: stop, revise, or controlled expansion
No automatic scale decision based on elapsed time.

A 90-day schedule organizes evidence collection; it is not a promise that transformation will be complete in three months.
