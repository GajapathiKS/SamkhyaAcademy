# Forward Deployed AI Leadership

## Module 1: AI Reality for Leaders

Evaluate AI proposals by capability, evidence and consequences of error.

### 1.1 LLM capability and limitations

Fluent output can conceal missing evidence. Ask what a proposed system does well, where it fails and who reviews consequential errors. A demonstration should include difficult and unanswerable cases, not only a polished success path.

### 1.2 RAG, fine-tuning and SLMs

Retrieval supplies external context; fine-tuning changes learned behavior; a smaller model may suit a bounded task. Ask which problem each choice solves and what evidence supports it. None removes the need for permissions, evaluation and an operating owner.

### 1.3 Agents and autonomous workflows

Autonomy changes who selects the next step and therefore changes risk. Map which actions are reversible, which require approval and where the system must stop. Do not equate an agent demonstration with permission to automate the whole business process.

### 1.4 Voice, vision and multimodal opportunities

Voice, image and document workflows can expand access but also introduce recognition errors and privacy concerns. Evaluate the entire user journey, including confirmation and correction. Ask whether a simpler interface would solve the same problem with fewer failure modes.

## Worked lab

Require: examples of unsupported questions and a denied change
