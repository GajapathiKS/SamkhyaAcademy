# Entrepreneurship & Venture Builder

## Module 4: MVP Build

Build the smallest demonstrator that tests the largest remaining uncertainty.

### 4.1 MVP scope

An MVP is a bounded learning experiment, not a smaller copy of every planned feature. Write the question it must answer and remove features that do not help answer it. A manual service or clickable prototype may be sufficient.

### 4.2 Prototype and architecture

Choose prototype fidelity based on the risk being tested. A clickable flow tests comprehension, while a working integration tests technical feasibility. Document what is simulated so feedback is not based on capabilities the prototype does not have.

### 4.3 Test plan

A test plan identifies participant criteria, task, observation method and decision threshold before the test. Include failure and abandonment, not just completion. Separate usability findings from evidence of willingness to pay.

### 4.4 MVP readiness review

Review scope, privacy, reliability and test readiness before exposing the prototype to participants. Course review checks the assignment evidence. A venture program’s MVP gate is a distinct decision with its own reviewer and artifact history.

## Worked lab

Learning question: can growers interpret an irrigation recommendation?
Prototype: three screens with synthetic weather data
Task: explain the recommendation and choose a next action
Observe: confusion, incorrect assumptions, confidence and abandonment
Boundary: no live agricultural advice is delivered.

A prototype can test comprehension without pretending to supply reliable real-world recommendations.
