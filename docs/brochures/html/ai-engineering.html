Detailed module curriculum · 1-3

Build the foundations.

The module names, lesson sequence and evidence below match the course learning workspace.

1Engineering Readiness Bridge

Prepare a dependable service boundary before adding a model.

  1. 1.1Backend/API readinessAn API contract specifies inputs, outputs, errors and permissions.
  2. 1.2Data and database readinessModel transactional records separately from retrieved documents and generated text.
  3. 1.3Testing and GitUse version control to make changes reviewable and tests to preserve contracts.
  4. 1.4Cloud foundationsA deployed service needs configuration, secrets, logs, health checks and a recovery plan.

You will produce: Service contract, fixture and boundary tests.

2AI Engineering

Build a grounded answer pipeline for approved knowledge sources.

  1. 2.1LLM foundationsAn LLM predicts output from context; fluent language does not prove factual accuracy.
  2. 2.2Prompt and context engineeringSeparate task instructions from retrieved evidence and user input.
  3. 2.3Structured output and toolsStructured output makes parsing predictable, but schema validity does not establish semantic correctness.
  4. 2.4Embeddings, vector databases and RAGEmbeddings support similarity search over representations of content.

You will produce: Grounded response set and retrieval evaluation.

3Agents, Voice and Multimodal AI

Choose bounded orchestration for tasks that combine tools and modalities.

  1. 3.1Agents, tasks and memoryAn agent selects steps within an allowed action space.
  2. 3.2MCP, skills and multi-agent patternsTool protocols and reusable skills can standardize integration, but they do not grant trust.
  3. 3.3STT, TTS and realtime agentsVoice adds turn-taking, interruption and latency concerns to a text workflow.
  4. 3.4Vision and document AIDocument and image workflows need provenance and uncertainty handling.

You will produce: Orchestration diagram and multimodal failure cases.

4Production AI Engineering

Measure and operate an AI service under realistic failure conditions.

  1. 4.1Evaluations and guardrailsAn evaluation set needs representative tasks, expected evidence and clear scoring criteria.
  2. 4.2Docker, CI/CD and cloudPackage a reproducible service and gate releases with tests.
  3. 4.3LLMOps and observabilityObserve latency, retrieval outcomes, model usage and tool decisions with request identifiers.
  4. 4.4Security, scale and costBound concurrency, token usage and retries.

You will produce: Evaluation report, operational dashboard plan and runbook.

5Enterprise Integration

Connect enterprise systems without bypassing identity or audit boundaries.

  1. 5.1SSO, OAuth/OIDC and RBACAuthentication identifies the caller; authorization determines allowed actions.
  2. 5.2Enterprise APIs and databasesAn adapter should expose a small, validated contract over the enterprise API or database.
  3. 5.3SharePoint, SAP and CRM integrationSharePoint, SAP and CRM are examples of enterprise information sources, not separate academy consulting offerings.
  4. 5.4Service platforms and legacy systemsLegacy and service-management systems may lack modern event guarantees.

You will produce: Adapter contract, access matrix and audit trace.

6Solution Architecture and Forward Deployment

Select a solution based on the customer’s workflow and evidence needs.

  1. 6.1RAG vs fine-tuning vs SLMUse retrieval when answers need current external evidence; consider adaptation when a measured behavior needs improvement.
  2. 6.2Agent vs deterministic workflowA deterministic workflow is preferable when steps and decisions are known.
  3. 6.3Customer discovery and value caseObserve the current workflow, identify users and establish a baseline before estimating value.
  4. 6.4Forward-deployment capstoneThe capstone combines discovery, architecture, an adapter, grounded behavior, evaluation and an operations plan.

You will produce: Architecture decision record and forward-deployment portfolio.
