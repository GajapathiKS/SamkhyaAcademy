Detailed module curriculum · 1-2

Build the foundations.

The module names, lesson sequence and evidence below match the course learning workspace.

1Web Foundations

Build a semantic, responsive profile page before adding a framework.

  1. 1.1Semantic HTMLHTML describes document meaning.
  2. 1.2Modern CSSCSS separates presentation from structure.
  3. 1.3JavaScript and TypeScriptJavaScript provides runtime behavior; TypeScript adds static checks during development.
  4. 1.4Accessibility and responsive designResponsive design adapts content and controls, not just font size.

You will produce: Responsive page and accessibility checklist.

2Frontend Engineering

Organize a frontend around components, explicit state and testable behavior.

  1. 2.1React or Angular foundationsA component has a focused responsibility and a clear input contract.
  2. 2.2State and formsState should represent the minimum information needed to render the interface.
  3. 2.3Data fetchingData fetching introduces loading, failure, empty and stale states.
  4. 2.4Frontend testingTest components through observable behavior.

You will produce: Component interface, state diagram and UI tests.

Practice is part of every module

Work through the example, record your reasoning, complete the module assignment and compare your work with the review criteria.

3Backend Specialization

Create an API that enforces rules independently of its user interface.

  1. 3.1API designAn API contract defines resource identity, validation, response shape and errors.
  2. 3.2Authentication and authorizationAuthentication establishes identity; authorization evaluates whether that identity may perform an operation on a resource.
  3. 3.3Validation and errorsValidate types, ranges and required relationships at the boundary.
  4. 3.4Backend testingBackend tests should exercise contracts, permissions and state transitions.

You will produce: API specification and permission regression tests.

4Data and Production

Connect data modeling, release practice and the final application.

  1. 4.1SQL modelingSQL modeling defines keys, relationships and constraints that protect data integrity.
  2. 4.2NoSQL patternsDocument-oriented data models trade joins for embedded or referenced structures.
  3. 4.3Docker and CI/CDA container packages an application environment; CI verifies and builds changes.
  4. 4.4Full-stack capstoneThe capstone integrates a responsive frontend, validated API, data model and tests.

You will produce: Full-stack capstone and deployment runbook.
