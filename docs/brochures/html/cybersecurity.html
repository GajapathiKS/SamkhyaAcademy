Detailed module curriculum · 1-2

Build the foundations.

The module names, lesson sequence and evidence below match the course learning workspace.

1Security Foundations

Review an isolated learning application using synthetic records and explicit authorization to test.

  1. 1.1Security principlesConfidentiality, integrity and availability describe different security needs.
  2. 1.2Threat actors and attack surfacesAn attack surface includes inputs, dependencies, interfaces and administrative access.
  3. 1.3Threat modelingA threat model connects actors, assets, trust boundaries and abuse cases.
  4. 1.4Security controlsPreventive, detective and recovery controls serve different purposes.

You will produce: Threat model and authorized test plan.

2Identity and Networks

Keep identity, permission and network exposure separate in the design.

  1. 2.1Authentication and authorizationAuthentication establishes who is calling; authorization decides what that caller may do.
  2. 2.2IAM and least privilegeLeast privilege limits permissions to the task and duration needed.
  3. 2.3Network securityNetwork controls restrict reachability but do not replace application authorization.
  4. 2.4Cloud security basicsCloud security includes identity, configuration, secrets, data protection and operational monitoring.

You will produce: Access matrix and boundary test evidence.

Practice is part of every module

Work through the example, record your reasoning, complete the module assignment and compare your work with the review criteria.

3Application Security

Validate application boundaries throughout development.

  1. 3.1OWASP risksUse risk categories as prompts for investigation, not a complete security checklist.
  2. 3.2Web and API securityValidate requests and enforce object-level permission before returning private data.
  3. 3.3Secrets and data protectionKeep secrets out of source code and browser bundles.
  4. 3.4Secure development lifecycleBuild security review into design, implementation, testing and release.

You will produce: Application review and remediation report.

4Monitoring and Response

Make security events useful for investigation and recovery.

  1. 4.1Security loggingA log should identify the event, time, actor or service and decision without exposing unnecessary sensitive payloads.
  2. 4.2Detection conceptsA detection rule maps observable behavior to a review signal.
  3. 4.3Incident responseAn incident process covers triage, containment, investigation, recovery and learning.
  4. 4.4Security review capstoneThe capstone presents scope, assets, findings, controls, residual risk and retest evidence.

You will produce: Security event plan, tabletop record and capstone report.

Inside module 1: a worked example

Asset: private project notes
Boundary: browser -> API -> database
Abuse case: learner requests another learner’s project
Control: server-side resource authorization
Evidence: authorized request succeeds; cross-user request is denied.

The exercise tests the boundary with synthetic accounts, not real users or third-party services.
